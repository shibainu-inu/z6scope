## 定義と前提

- **境界** = `meta.last_export_max:{room}`（最新 `/export` の最大 seq）。
- **前提**（09-02/03 実測。ルール 7 により公開前に再検証する）: `/export` は連続した
  1 本のリングを返し、サーバの seq は連番である。この前提の下で、境界以下で欠けて
  いる seq はリング最古値より前 = **恒久喪失**。境界より上の欠けは head ポーリング
  のみの範囲で次の export で埋まりうる = **未確定**（上限値、時間で変動）。
- **残余**: `messages` に無くても `raw/` に JSONL 行として残っている可能性がある
  （パースに失敗した行は警告ログのみで `parse_failures` に行が入らない。collector は
  ログファイルを持たないので、ログでは再現確認できない）。公開前に
  `python3 docs/coverage_check.py --raw-residual` を実行する: `raw/` の全ファイルを
  読み直し、境界以下で raw にあって `messages` に無い seq と、パースできない JSONL 行を
  数える（`--reparse` で回収できるので「恒久喪失」ではない）。結果は下の検証記録。
- **保有** = `COUNT(*)`。公開時は「少なくとも」。
- **再現可能な列**: `present_at_boundary` / `span_at_boundary` は seq ≤ 境界に限定。
  同じ境界で再実行すれば head が伸びても同じ値になる。公開にはこちらを使う。
- **証拠にならないもの**: `present + lost + pending = span` は `PRIMARY KEY (room, seq)`
  と `LAG` の分割により恒等的に成り立つ（失敗しえない）ので、検証ではない。
  重複 seq の検査も同じ PK により恒等的に 0 なので載せない。失敗しうるチェックは
  `sanity_boundary_in_span`（1）と `sanity_no_boundary`（0）の 2 つ。独立した第 2 の
  導出は `coverage_check.py`（集合差、window 関数を使わない。`-- (A)` マーカーから
  実 SQL を読んで突き合わせ、ルーム集合の一致も確認する）。
